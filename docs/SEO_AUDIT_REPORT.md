### Платформа: OcStore (OpenCart 3), тема evrika
### Дата: 2026-05-28 | Среда: dev-сервер, демо-контент

---

> ⚠️ **Важно:** аудит проводился на dev-среде с демо-данными. Все выводы по контенту (тексты,
> мета-теги, изображения) носят структурный характер — финальная оценка возможна только на

## Блок 1 — Технический фундамент

### Найдено проблем: 8 (критических: 3, важных: 4, рекомендаций: 1)

---

### 🔴 Критические

**1. Отсутствует canonical URL на всех страницах**
- Нет ни одного `<link rel="canonical">` в коде
- Угроза: OcStore генерирует дубли — `/index.php?route=product/category&path=59` и `/kanctovar/ruchki/` ведут на один контент; пагинация `/page=2` дублирует базовую страницу
- Где исправить: `header.twig` — добавить canonical через OCMod-патч контроллера или напрямую в шаблон

**2. Отсутствует sitemap.xml**
- Файл не существует. В `robots.txt` строка Sitemap закомментирована (строка 47):
  ```
  # Sitemap: https://site.com/sitemap.xml
  ```
- Угроза: поисковики не знают о страницах сайта, индексация замедлена
- Где исправить: включить модуль XML Sitemap в OcStore (Extensions → Extensions → Feeds) или плагин SeoPro

**3. Главная страница не имеет H1**
- `home.twig` не содержит ни одного тега `<h1>` — ни статического, ни динамического
- Весь визуальный контент (слайдер, секции) рендерится через `{{ content_top }}` / `{{ content_bottom }}` без заголовка
- Угроза: поисковик не получает основной тематический сигнал главной страницы
- Где исправить: `home.twig` — добавить визуально скрытый или видимый H1

---

### 🟡 Важные

**4. Render-blocking скрипты в `<head>`**
- Два тяжёлых скрипта загружаются синхронно (блокируют рендер):
  - Строка 19: `jquery-2.1.1.min.js` — без `defer`/`async`
  - Строка 20: `bootstrap.min.js` — без `defer`/`async`
- OcStore loop для `scripts` (строки 47–49) также без defer
- Угроза: замедление FCP/LCP, потеря позиций в Core Web Vitals
- Примечание: jQuery нельзя делать defer, если он используется в inline-скриптах в `<body>` — требует анализа

**5. Главное изображение товара загружается с `loading="lazy"`**
- `product.twig`, строка 39: `<img src="{{ thumb }}" alt="{{ heading_title }}" id="mainImage">`
- Атрибут `loading="lazy"` НЕ указан явно, но и `fetchpriority="high"` тоже отсутствует
- Угроза: браузер может отложить загрузку hero-изображения → ухудшение LCP
- Где исправить: добавить `fetchpriority="high"` на главное изображение товара

**6. Отсутствуют атрибуты `width` и `height` у всех изображений**
- Ни в `product.twig`, ни в `category.twig` нет явных размеров
- Угроза: CLS (Cumulative Layout Shift) — страница «прыгает» при загрузке изображений
- Где исправить: добавить `width` и `height` в шаблоны. OcStore знает размеры через настройки `image_resize`

**7. `og:type` жёстко задан как `"website"` на всех страницах**
- `header.twig`, строка 13: `<meta property="og:type" content="website">`
- На страницах товаров должно быть `"product"`, на категориях — `"website"` или `"object"`
- Угроза: некорректное отображение при шаринге товаров в соцсетях/мессенджерах

---

### 📋 Рекомендации

**8. Удалить или оставить условным `<meta name="keywords">`**
- Строка 11 `header.twig`: `{% if keywords %}...{% endif %}` — тег выводится если заполнен
- Google игнорирует, Яндекс использует очень слабо; риска нет, но засоряет код
- Рекомендация: оставить условным (как есть), не заполнять вручную

---

### ✅ Уже реализовано корректно

- `robots.txt` — хорошая структура: закрыты служебные роуты, параметры фильтрации, sort/order/limit; открыта статика (css, js, изображения, шрифты)
- Open Graph теги: `og:title`, `og:description`, `og:url`, `og:image`, `og:site_name` — все присутствуют
- Google Fonts: `preconnect` на оба домена + `display=swap`
- `<meta name="viewport">` корректный
- Динамический `<title>` через `{{ title }}`
- Условный `<meta name="robots">` (для noindex отдельных страниц)

## Блок 2 — Архитектура URL

### Найдено проблем: 3 (критических: 1, важных: 2, рекомендаций: 0)

---

### 🔴 Критические

**1. SEO URL-псевдонимы для демо-контента не настроены**
- На dev-сервере категории и товары доступны по `?route=product/category&path=XX`
- Без SEO-псевдонимов (`Catalog → Categories → SEO → Keyword`) ЧПУ не работают
- Угроза: все URL содержат `index.php?route=` — катастрофа для SEO

---

### 🟡 Важные

**2. Дублирование через параметры пагинации**
- `/kanctovar/ruchki/?page=1` дублирует `/kanctovar/ruchki/`
- Не закрыто в robots.txt (параметр `?page=` не запрещён)
- Решение: canonical на базовый URL + закрыть `?page=` в robots.txt (осторожно — Яндекс использует rel=prev/next)

**3. Параметры фильтров в robots.txt покрыты не полностью**
- Закрыты: `?sort=`, `?order=`, `?limit=`, `?filter=`, `?filter_name=`, `?filter_sub_category=`
- Не закрыты: `?page=`, `?manufacturer_id=` (частично — только через `product*&manufacturer_id=`)
- OcStore может генерировать другие комбинации параметров

---

### ✅ Уже реализовано корректно

- robots.txt закрывает основные параметры фильтрации
- Разрешена индексация статики (шрифты, картинки, скрипты)
- SEO URL в OcStore включены (настройка `System → Settings → Server → Use SEO URLs`)

---

## Блок 3 — Мета-теги

### Найдено проблем: 4 (критических: 1, важных: 2, рекомендаций: 1)

---

### 🔴 Критические

**1. Шаблоны авто-генерации мета-тегов отсутствуют**
- OcStore без OCMod использует только то, что заполнено в админке вручную
- На демо-контенте title = название страницы, description = пусто
- Для каталога в 1000+ SKU ручное заполнение нереально
- Решение: OCMod-патч для автоматического формирования title/description по шаблону (см. ТЗ для разработчика)

---

### 🟡 Важные

**2. `og:description` отсутствует как отдельный тег**
- В header.twig есть `og:title`, `og:image`, но нет `<meta property="og:description">`
- При шаринге ВКонтакте/Telegram описание не подтянется
- Решение: добавить `<meta property="og:description" content="{{ description }}">`

**3. Страницы пагинации не имеют уникальных title**
- `/kanctovar/ruchki/?page=2` получает тот же title что и первая страница
- Яндекс может воспринять как дубль
- Решение: OCMod-патч — добавить ` — страница {{ get.page }}` в title при наличии параметра `page`

---

### 📋 Рекомендации

**4. Добавить `og:locale` и `og:locale:alternate`**
- Для русскоязычного магазина полезно указать: `<meta property="og:locale" content="ru_RU">`
- Низкий приоритет, но улучшает распознавание региона в соцсетях

---

### ✅ Уже реализовано корректно

- `og:title`, `og:url`, `og:image`, `og:site_name` присутствуют
- Динамический title через `{{ title }}`
- Условный meta description (выводится если заполнен в админке)
- Условный meta robots (для управления noindex)

## Блок 5 — Микроразметка Schema.org

### Найдено проблем: 5 (критических: 4, важных: 1, рекомендаций: 0)

---

### 🔴 Критические

**1. Отсутствует разметка LocalBusiness / Organization**
- В `header.twig` нет ни одного `<script type="application/ld+json">` с данными организации
- Яндекс и Google не получают структурированных данных о компании, адресе, телефоне, режиме работы
- Максимальный приоритет для локального SEO

**2. Отсутствует BreadcrumbList Schema.org**
- `breadcrumb.twig` — только HTML `<nav>`, без JSON-LD и без `itemscope/itemtype`
- Поисковики не показывают хлебные крошки в сниппете SERP

**3. Отсутствует Product Schema.org на страницах товаров**
- `product.twig` — ноль структурированных данных
- Без Product schema: нет rich snippets с ценой, рейтингом, наличием в выдаче Google
- Яндекс также использует Product schema для расширенных сниппетов
- Критично для конверсии из поиска

**4. Отсутствует ItemList Schema.org на страницах категорий**
- `category.twig` — нет разметки списка товаров
- Упущенная возможность для rich results в Google

---

### 🟡 Важные

**5. Отсутствует WebSite Schema.org с SearchAction (Sitelinks Searchbox)**
- Главная страница без `WebSite` + `potentialAction: SearchAction`
- Google может показывать поисковую строку прямо в SERP (Sitelinks Searchbox)
- Для B2B-магазина с широким каталогом — значимый UX-сигнал

---

### ✅ Уже реализовано корректно

- Семантические HTML-теги: `<nav>`, `<main>`, `<article>`, `<aside>`, `<footer>` — присутствуют
- ARIA-атрибуты на интерактивных элементах
- Хлебные крошки технически корректны (HTML-структура)

## Блок 7 — Локальное SEO

### Найдено проблем: 4 (критических: 1, важных: 3, рекомендаций: 0)

---

### 🔴 Критические

**1. Адрес/телефон в `footer.twig` и `header.twig` — не в структуре Schema.org**
- Контактные данные выводятся как `{{ telephone }}`, `{{ address }}` — чистый текст
- Без разметки `LocalBusiness` в JSON-LD поисковики не связывают контент сайта с геоданными
- Критично для Яндекс Бизнес и локальных запросов «оптом Мелитополь»

---

### 🟡 Важные

**2. Город (Мелитополь) не упомянут в шаблонах заголовков**
- В `header.twig` нет статического упоминания города в title по умолчанию
- Шаблон title категории/товара не включает регион
- Решение: в шаблонах авто-генерации title добавить «в Мелитополе» для категорий

**3. NAP-consistency (Name/Address/Phone) невозможно проверить на dev**
- На продакшене нужно убедиться что телефон и адрес одинаковы в: топбаре, футере, странице контактов, Schema.org, Яндекс.Бизнес, Google Business

**4. Время работы не размечено структурированно**
- В `footer.twig` (строки 22–26) есть блок с часами работы — чистый HTML/текст
- Без `OpeningHoursSpecification` в Schema.org Яндекс не показывает часы в сниппете

---

### ✅ Уже реализовано корректно

- Телефон в шапке кликабелен (`href="tel:..."`)
- Адрес выводится в подвале
- Топбар содержит телефон
